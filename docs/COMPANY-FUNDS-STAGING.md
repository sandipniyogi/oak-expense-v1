# Company funds staging package — recreated v2

This replaces the unavailable transient v1 download. It recreates the company withdrawals/advances and monthly settlement feature, and is not a byte-identical copy of v1. It does not replace tools/ or any sync/deployment control panel.

Use a separate feature/company-funds branch based on approved origin/main; leave unfinished synchronization PR #9 on staging. Do not delete or stash untracked tools/ blindly. The source installer refuses another branch, modified source anchors, symlinks and unexpected existing feature files. It patches only the API route registration and a homepage navigation link, backs up those source files and adds the feature source. It does not start Docker or run SQL.

After source installation: `python3 scripts/start-company-funds-staging.py`. No Mac Node installation is needed. Existing staging database/API containers must run. The helper first executes the 13 calculation tests plus real Express/PostgreSQL tests against a newly created disposable database, then drops it. It builds API/web, saves and catalog-verifies a staging PG dump, applies the two new tables, and recreates only staging API/web with OAK_COMPANY_FUNDS=1 and OAK_STRICT_SYNC=0. It validates the staging project/uploads/database volume and checks API/page health. It does not restart Mac live/VPS, delete volumes or copy live data into staging.

Visit http://localhost:3100/company-funds. Record CNY advances, returns, reimbursements, capital, drawings or explicit opening adjustments with individual, date and purpose/bank reference. Retry request IDs prevent repeated saves from inserting a second movement. Correct wrong movements by voiding with a reason and adding a corrected entry; old records remain in history.

Review each existing expense as personal money, company-advance spending or a direct company payment. Each expense can be linked only once, without creating another expense. Direct company payments require the existing Paid by to be Company; other funding requires an individual. Expense amount or Paid by changes invalidate the review. Legacy/unreviewed and unsupported-currency expenses are excluded; the report displays a provisional warning until review is complete. Existing reimbursement_status flags are not automatically treated as ledger payouts: enter reimbursements once and do not double-count past balances.

Monthly positive closing net means company owes the person; negative means company money held/owed by that person. Formula: prior opening + reviewed business costs (personal and advance-funded) + returns - company advances - reimbursements + opening adjustments. Prior balances carry forward. Capital contributions and personal drawings are separate from reimbursement net. Opening adjustments must not duplicate earlier costs/movements. Direct company expenses and company cash-flow totals are separately displayed. This is not a bank reconciliation. Negative advance cash held suggests missing transfers or classification needing review.

Examples: 5000 advance - 3200 advance-funded spending - 1000 returned leaves 800 held. 8000 reviewed costs - 5000 advance - 1000 reimbursement leaves 2000 owed. Company advances do not count again as expenses. Reports recalculate from records; final monthly closing/sign-off, scheduled notifications, FX/refunds, splitting one expense across people, bank-account reconciliation and new-report export are not in this version. Movement receipt upload is not implemented; existing expense receipts can be opened. Linked expenses cannot be deleted until their evidence linkage is explicitly dealt with.

Thirteen model tests pass in the preparation environment. Docker/PostgreSQL integration and the Next.js build have not run there; they run via the Mac helper. Browser/mobile behavior needs your staging review. This feature uses the existing app access protection and adds no new operator authentication or identity audit.

Do not deploy this schema to Mac live or VPS yet: the new tables are not supported by the existing expense-only sync or application-role scope. A live release needs migration, permissions and sync/backup scope review. Keep PR #9 draft. The current pre-push hook supports staging only; do not bypass it to publish this feature branch. Downloads is only a transfer location; installed project source lives in Desktop/oak-expense-v1.
